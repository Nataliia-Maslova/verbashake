## ✅ 1. Прогрес-бар Vocabulary показував 10239% замість 100%

**Файл:** [app.py:281-286](app.py#L281) (`_module_progress`, гілка `else`).
**Причина:** `completed = max(saved_lesson - 1, 0)` не обмежувалось через
`min(..., total)`, на відміну від сусідньої гілки. Для CEFR-J vocab
`saved_lesson` — глобальний ID (100000+), а не 1..981 — ділення на `total`
вибухало.
**Фікс:** `completed = min(max(saved_lesson - 1, 0), total)`.
**Перевірено вживу**: картка Vocabulary на лаунчері тепер показує рівно
`Topic 100% / 981 / 981`.

## ✅ 2. Текст ламався посеред слова ("Vocabular|y", "Висловлюван|ня", "Пропустит|и")

Виявилось глибше, ніж одна CSS-властивість — `word-break: keep-all` сам по
собі НЕ рятує (для не-CJK тексту він поводиться як `normal`, а
`overflow-wrap: break-word` все одно ламає слово, якщо воно фізично не
влазить). Реальний фікс — зменшити розмір шрифту/розширити колонку так, щоб
найдовше реальне слово влазило цілим.

- [app.py](app.py) `.mode-title` (картки модулів) — розмір зменшено з
  `clamp(.85rem,2.4vw,1.1rem)` до `clamp(.68rem,1.6vw,.82rem)` +
  `white-space:nowrap`. **Перевірено**: "Grammar/Vocabulary/Phrasebook/
  Reading/My Phrases/My Path" — усі в один рядок.
- [static/mova/streamlit-overrides.css](static/mova/streamlit-overrides.css)
  `.stButton > button` — розмір тепер `clamp(0.74rem, 1.3vw, 0.95rem)`
  замість фіксованих 15px, глобально для всіх кнопок застосунку.
- [grammar.py](grammar.py) фазова навігація (Розминка/Новий матеріал/
  Практика/Висловлювання/Відео) — додатковий скоуп `.st-key-phase_nav_row`
  з `font-size:0.7rem`. **Перевірено**: "Висловлювання" тепер в один рядок.
- [grammar.py](grammar.py) кнопка "Пропустити →" — сама колонка була
  зафіксовано занадто вузькою (`st.columns([5,1])`), жоден розмір шрифту не
  рятував. Змінено на `st.columns([4, 1.5])`. **Перевірено**: "Пропустити →"
  в один рядок.

**Важливий нюанс для майбутніх сесій**: CSS-файли (`static/mova/*.css`)
читаються через `_read_mova_css()`, декорований `@st.cache_data` в app.py —
зміни в CSS-файлах НЕ підхоплюються навіть з `runOnSave` без повного
рестарту процесу Streamlit (на відміну від змін у `.py`-файлах, які тепер
підхоплюються на льоту — див. нижче).

**6. ✅ Dark mode toggle — найризикованіший пункт, знайшла і виправила

палітру. Додано перемикач `🌙 Dark mode` в сайдбар

виставлення `data-theme` на `<html>` — `st.markdown` не міг би це зробити,
браузери не виконують `<script>`, вставлений через `innerHTML`.

Перша версія спрацювала лише частково: сайдбар і картки коректно
перефарбувались, а фон `.stApp` (основний контент) лишався світлим навіть
попри `!important` у CSS-правилі. Продіагностувала через DevTools-подібні
JS-запити: `--mova-surface` як CSS-змінна дійсно резолвилась у темне
значення на `.stApp`, але щось у власній генерованій CSS Стрімліта все одно
малювало світлий фон. Замість продовжувати боротьбу за специфічність CSS —
виставляю колір напряму через inline-style з `!important` через той самий
JS (`element.style.setProperty('background', 'var(--mova-surface)',
'important')`) — inline-стиль з `!important` б'є будь-яке CSS-правило за
специфічністю, незалежно від того що робить Streamlit. Перевірено вживу:
весь застосунок (сайдбар, фон, картки, текст) коректно перемикається між
світлою і темною темою.

**Не персиститься між сесіями** (свідомо) — `key="_dark_mode"` живе тільки
в `st.session_state`, не в БД. Досить дешево додати збереження на
per-user рівні пізніше, якщо Наталя захоче.

## Технічні нотатки для наступної сесії

- **`.streamlit/config.toml`**: додано `runOnSave = true` в `[server]` —
  тепер зміни в `.py`-файлах підхоплюються на простому перезавантаженні
  сторінки (не потрібен рестарт процесу). Разом з цим у `venv` встановлено
  `watchdog` (`pip install watchdog`) — без нього Streamlit взагалі не
  відстежує зміни файлів. Обидві зміни безпечні й лишені в проєкті навмисно
  — прискорюють будь-яку наступну сесію розробки. Якщо це небажано —
  відкатити `runOnSave` на `false` (або прибрати рядок).
- **CSS-файли (`static/mova/*.css`) — виняток**: через `@st.cache_data` на
  `_read_mova_css()` в app.py зміни в CSS не підхоплюються навіть з
  `runOnSave`. Для CSS-правок завжди потрібен повний рестарт процесу:
