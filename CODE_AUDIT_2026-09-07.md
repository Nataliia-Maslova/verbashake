# Глубокий код-ревью VerbaShake — 2026-09-07

Полная проверка кода приложения по запросу Наталі, вторая с 2026-08-28. 8 параллельных агентов прочитали весь репозиторий (~18K строк вне venv/scripts), затем найденное было проверено чтением кода и живыми тестами через Claude in Chrome, и все однозначные баги исправлены напрямую.

---

## Часть 1 — Исправлено сразу (первый проход)

Все проверены `py_compile`, часть — живьём в браузере.

1. **`grammar.py::_record_mistake()` хардкодил `module="grammar"`** — ошибка в уроке Vocabulary/Phrasebook классифицировалась против тем Grammar-модуля и могла дингнуть mastery/SRS несвязанного Grammar-урока. Исправлено на `_current_module()`.
2. **`engine/gemini.py` — 6 мест с незащищённым `.text.strip()`** — Gemini иногда возвращает `text=None` (safety-filter, MAX_TOKENS без частей), что крашило `AttributeError` посреди roleplay/tutor-чата. Добавлен `_safe_text()`.
3. **`engine/schedule.py::save_schedule()`** — неатомарный DELETE+INSERT, молча проглатывал ошибку, а UI всегда показывал «Сохранено.» Теперь возвращает `bool`, UI показывает ошибку при неудаче.
4. **`reading_app.py:2071`** — тот же баг со старым 4-язычным словарём, что уже чинили в `grammar.py` 28 августа (язык «не с той стороны» → всегда фолбек на `en`). Заменено на `_recommender.LANG_TO_CODE`.
5. **Тёмная тема сбрасывалась** — не сохранялась ни в одном из 7 мест, что очищают `session_state` (завершение урока, все варианты переключения модуля). Исправлено везде.
6. **Завершение урока, открытого напрямую из сайдбара**, кидало на верхний лаунчер вместо возврата в модуль — точечный фикс на пути завершения урока.
7. **`custom_app.py` показывал сырую exception в UI** при неудачном сохранении урока — заменено на локализованное сообщение (тот же класс утечки, что уже чинили для Stripe).
8. **`engine/recommender.py::seed_mastery_from_level()`** — незащищённые `db.fetch_all()` могли уронить онбординг при обрыве связи с Supabase. Обёрнуто в try/except.

### Собственная ошибка, пойманная и исправленная вслух

Чуть не убрала `ENABLE ROW LEVEL SECURITY` на 14 таблицах, посчитав его бесполезным (роль-владелец обходит RLS). Перечитала `schema.sql` перед правкой — обнаружила комментарий от предыдущей сессии (28.08): RLS-без-policy — это **default-deny для публичного Supabase PostgREST API** (`anon`-ключ), а не для собственного подключения приложения. Без этого кто угодно со ссылкой на проект мог бы читать/писать таблицы напрямую. Оставлено как есть — это осознанное и уже проверенное решение, не недосмотр.

### Первая неудачная попытка (для истории)

Таймзону сначала пыталась поймать тем же JS-трюком, что dark mode/PWA-инъекция (`components.html` → `window.parent.location.replace()`). Не сработало: iframe в этой версии Streamlit (1.61.1) имеет `sandbox` без `allow-top-navigation` — DOM-манипуляции работают, а навигация верхнего фрейма молча блокируется браузером без единой ошибки в консоли. Найдено правильное решение — встроенный `st.context.timezone`.

### Побочная находка

Локальный dev-сервер (запущен с прошлых сессий) перестал подхватывать изменения файлов — `streamlit`-вотчер падает на `ModuleNotFoundError: No module named 'torchvision'` при сканировании `transformers`. Перезапустила сервер как временное решение; саму зависимость не трогала.

## Осталось на очереди (не исправлено сознательно)

Требует более крупного объёма работы или решения о рисках:

- **Гонка в `engine/signup_gate.py::check_and_admit()`** (read-count-then-insert) — низкий риск (маркетинговый лимит, «fail open» по дизайну), но исправление потребовало бы добавлять транзакционную инфраструктуру, которой сейчас нет в `engine/db.py`. Решила не трогать транзакционную семантику ради низкорисковой находки.
